# Кинема — Upper Limb Motion Lab

Подробное описание архитектуры, всех систем, формул метрик, анкеты, персонализированных правил, API и ограничений: [документация программы](docs/PROGRAM_DOCUMENTATION_RU.md).

Демонстрационный вымышленный пациент: `python -m scripts.create_demo`. Анкета и сценарий показа находятся в [examples/DEMO_GUIDE.md](examples/DEMO_GUIDE.md). Пример отмечен в интерфейсе как демо; его видео — синтетическая схема без MediaPipe inference.

Запускаемый локальный исследовательский MVP для измерения движения верхней конечности по видео. Интерфейс на русском: загрузка MP4/MOV/WebM, выбор стороны и задания, просмотр видео с canvas-скелетом, траектории кистей, синхронные графики, сравнение сторон, отчёт, экспорт JSON и полное удаление исследования.

**Исследовательский прототип без клинической валидации.** Измерения в плоскости камеры не эквивалентны клинической гониометрии. Evidence Service подбирает проверенные источники по темам измерений и формирует отдельный контекст литературы и вопросы о направлениях реабилитации для специалиста. Приложение не ставит диагноз, не определяет индивидуальные показания/противопоказания и не назначает лечение.

## Установка и запуск

Для повседневного запуска установленного проекта дважды щёлкните **Start-Kinema.bat** в корне проекта. Он запускает сервер и открывает приложение в браузере. Если сервер уже работает, просто открывается приложение. Оставьте окно сервера открытым; для остановки нажмите Ctrl+C. Можно создать ярлык этого файла на рабочем столе через контекстное меню Windows («Отправить → Рабочий стол (создать ярлык)»).

Адрес приложения можно сохранить в закладках: **http://127.0.0.1:8000**. Закладка открывает интерфейс, когда сервер запущен. Поиск PubMed требует доступа к интернету; запуск через этот файл из обычного Проводника Windows использует сетевые разрешения пользователя.

Проверенная среда: Windows, Python 3.10, Node.js 24; рекомендуется Python 3.10–3.12 и Node.js 22+. Системный FFmpeg не нужен: декодирование и H.264-экспорт выполняет PyAV. Требуется интернет при установке пакетов и однократном скачивании модели. Измерения и подбор из проверенного каталога работают локально без сети. После анализа видео и сохранения анкеты автоматически выполняется отдельный поиск PubMed по общим категориям пациента; при отсутствии интернета отчёт сохраняется с предупреждением. В результатах появляется блок «Литература для оценки этого пациента»: темы, основания подбора, запросы, даты и ссылки; это материалы для врача, а не подтверждённый диагноз или назначение.

Интеграционный тест использует настоящую локальную модель: установите её перед запуском. В тестах нет медицинских видео; используется сгенерированный пустой MP4 и синтетические landmarks с известной геометрией. Проверяются углы, нормализация, разные соотношения сторон изображения, скорость при переменном шаге времени, сглаживание, пропуски, ROM, индекс асимметрии, отсутствие выдуманных данных, загрузка, сохранение и удаление. Такие тесты проверяют реализацию, а не клиническую точность модели.

При разработке также пройден HTTP smoke test с публичным [тестовым изображением MediaPipe](https://storage.googleapis.com/mediapipe-assets/pose.jpg), повторённым в 30-кадровом видео: обнаружение человека, углы обоих локтей, сохранённый отчёт, Range-запрос MP4 и полное удаление тестового исследования. Это статичная проверка интеграции, не проверка движения пациента. Повторение: скачайте изображение в `.validation/public_pose.jpg`, запустите сервер и выполните `python -m scripts.verify_local`. Скрипт удаляет созданное им исследование. Визуальная проверка интерфейса во встроенном браузере среды разработки была недоступна из-за блокировки localhost; TypeScript и production-сборка проверены.

## Структура и pipeline

```text
backend/app/
  main.py                API, проверки запросов, локальная очередь
  storage.py             независимые JSON-файлы, атомарная запись
  pipeline.py            оркестрация обработки
  video/                 валидация, декодирование PTS, MP4 для браузера
  pose/                  PoseProvider и MediaPipeProvider
  biomechanics/          независимая детерминированная математика
  movement_analysis/     признаки, кандидаты фаз, асимметрия, качество
  evidence/              проверенный каталог, PubMed API, подбор и provenance
  recommendations/       обоснованный контекст, направления, безопасность
  report/                наблюдения, ограничения, JSON без NaN
backend/tests/           unit и API/inference integration tests
frontend/src/            React + TypeScript + Recharts + canvas overlay
scripts/download_model.py
models/                  локальные веса, не включаются в Git
data/<study_id>/          локальные данные, не включаются в Git
```

```text
Upload → проверка размера/контейнера → decoded frames + PTS
→ MediaPipe VIDEO → исходные landmarks + confidence
→ исключение ненадёжных точек → сглаживание без заполнения пропусков
→ коррекция aspect ratio → нормализация по исходной медианной ширине плеч
→ проекционные суставные углы → скорости и траектории
→ эвристические события → сравнение сторон → объективный отчёт
```

Модель заменяется реализацией `PoseProvider.detect(rgb, timestamp_ms)` и `close()`; её экземпляр создаётся в `pipeline.py`. Возвращается словарь канонических landmarks и число людей. Для добавления кистей/нижних конечностей расширьте каноническую схему, отдельные функции признаков и соответствующие тесты. Расчёты не используют LLM.

Видео обрабатывает один background worker. Очередь ограничена одним исследованием; второй запрос получает 409. Это однопользовательский прототип: запускайте **один процесс Uvicorn без `--workers`**. При перезапуске незавершённые исследования помечаются ошибкой. Для масштабирования нужны persistent job queue, отдельные workers, БД и согласованная блокировка удаления.

## API

| Метод | URL | Назначение |
|---|---|---|
| GET | `/api/health` | Состояние сервера и наличие модели |
| POST | `/api/studies` | multipart: `file`, `affected_side`, `task`; ответ 202 с ID |
| GET | `/api/studies` | Сохранённые исследования |
| GET | `/api/studies/{id}` | Статус, прогресс, ошибки |
| GET | `/api/studies/{id}/report` | Структурированный отчёт; 409 до готовности |
| POST | `/api/studies/{id}/evidence` | Обновить контекст; JSON `online`, `topic` |
| GET | `/api/studies/{id}/files/{kind}` | original, preview, landmarks, metrics, report, evidence |
| DELETE | `/api/studies/{id}` | Полное удаление файлов; 409 во время обработки |

`affected_side`: `left`, `right`, `unknown` (по умолчанию). Стороны анатомические, не экранные. Отзеркалённое видео нужно предварительно исправить.

`task`: `unspecified` (по умолчанию), `forward_raise`, `side_raise`, `overhead`, `elbow`, `reach`, `hand_to_mouth`, `opposite_shoulder`, `free`. Выбор задания сохраняется как контекст; упражнение не классифицируется и метрики не интерпретируются клинически.

Ограничения загрузки: 300 МБ, 180 с, 12000 кадров, от 64×64 до 3840×2160. Расширение и реальное декодирование проверяются отдельно. Ошибки: 413 размер, 415 расширение, 422 некорректное видео/параметры, 503 нет модели. MOV/WebM могут не воспроизводиться непосредственно в браузере; pipeline создаёт MP4 H.264 без звука, с исходными временными метками. Оригинал сохраняется без изменений. Видео с rotation metadata/display matrix отклоняются: экспортируйте в правильной ориентации.

## Данные и воспроизводимость

```text
data/<id>/
  original.mp4|mov|webm   исходное видео
  preview.mp4            совместимая копия без звука
  study.json             параметры и статус
  landmarks.json         исходные координаты и confidence каждого кадра
  metrics.json           метрики, временные ряды и нормализация
  report.json            итоговый отчёт и provenance
  evidence.json          источники, темы, поисковый запрос и даты проверки
```

Landmark: `{x, y, z, visibility, presence, confidence, timestamp}`. `x,y` нормализованы размером изображения; `z` — относительная глубина модели, сохраняется, но не используется в 2D-метриках. `confidence=min(visibility,presence)`. Кадр: `frame_index`, `timestamp` в секундах, `people`, `landmarks`. При отсутствии человека/нескольких людях координаты не подставляются. Это не гарантирует устойчивую идентификацию, если люди сменяют друг друга в кадре; снимайте одного пациента.

Структура отчёта:

```json
{
  "schema_version": "1.1",
  "video_quality": {},
  "pose_quality": {},
  "metrics": {"left_arm": {}, "right_arm": {}, "trunk": {}},
  "asymmetry": {},
  "normalization": {},
  "series": [],
  "events": [],
  "observations": [],
  "limitations": [],
  "clinical_context": [],
  "rehabilitation_options": [],
  "evidence_status": "reviewed_catalog",
  "evidence": {},
  "evidence_disagreements": [],
  "safety_screen": {},
  "provenance": {}
}
```

Метрика: `{value, unit, coverage, valid_frames, technical_reliability, status}`. Отсутствующие значения — `null`, не нули. `coverage` — доля пригодных кадров. Минимум 5 значений и покрытие ≥60%; надёжность «high» при ≥90%, иначе «medium». Это технические пороги прототипа, **не вероятность правильного медицинского вывода** и не доверительный интервал. Ошибочные high-confidence landmarks всё равно возможны: проверяйте наложенный скелет.

Provenance включает SHA256 видео и весов, версию MediaPipe, версию алгоритма, временные параметры и дату UTC. Экстремумы сохраняются с полной расчётной точностью для исследований; интерфейс округляет значения. Источники раздельны, поэтому можно повторно рассчитать метрики из сохранённых landmarks без повторного inference.

## Определения показателей

- Перед геометрией `x*width`, `y*height`: иначе несогласованные масштабы x/y искажают углы.
- Угол локтя: плечо → локоть → запястье, 180° при прямой руке.
- Подъём плеча: таз той же стороны → плечо → локоть; 0° вдоль корпуса вниз, около 90° вбок в проекции. Не разделяет сгибание и отведение.
- ROM: максимум минус минимум достоверных значений за всё видео. Максимальный угол показывается отдельно.
- Координаты кисти: относительно центра плеч, делённые на фиксированную медианную ширину плеч. Скорость в ШП/с; это не м/с. При отсутствии надёжной ширины нормализованные показатели не выдаются.
- Сглаживание: скользящее среднее в окне 0,15 с внутри непрерывных участков; пропуски не заполняются. Оно может ослаблять пики. Оригинальные landmarks сохраняются.
- Производная: конечные разности NumPy по реальным decoded PTS в секундах. Не вычисляется через пропуски/разрывы >0,25 с; нужен участок ≥3 кадров. Пиковые скорости чувствительны к шуму.
- Длина траектории суммируется только по наблюдаемым непрерывным участкам, не включает пропущенные фрагменты.
- Вариабельность скорости: CV = стандартное отклонение / среднее; при почти неподвижной кисти значение отсутствует. Среднее и CV в этой версии усредняются по кадрам, поэтому видео с резко изменяющимся FPS требует проверки. CV не является валидированной клинической метрикой плавности.
- Наклон корпуса: линия центр таза → центр плеч относительно вертикали изображения; изменение относительно медианы первых 0,5 с (минимум 3 пригодных кадра).
- Подъём плечевого пояса: вертикальное смещение плеча относительно центра таза и исходного уровня, в ШП. Это не измерение лопатки.
- Голова: боковой диапазон носа относительно центра плеч, без углов головы.
- Индекс асимметрии: `200*abs(L-R)/(abs(L)+abs(R))`, диапазон 0–200%; при обоих нулях/пропуске не определён. Исходные значения всегда рядом. Нельзя сравнивать последовательные разные задания как идентичные движения.
- События: максимум измеренного подъёма; начало/возвращение — только кандидаты при изменении ≥15° и пересечении исходного уровня +10°. Для повторных движений выделяется один глобальный максимум. Нажатие переводит видео к соответствующему кадру.

Количество остановок, трёхмерный поворот корпуса, движение лопатки, автоматическое определение ограничения разгибания, причин компенсации и клиническая плавность **пока не реализованы**; не подменяются догадками.

## Клинические и технические ограничения

Нужны один человек, неподвижная камера, контрастное освещение, видимые плечи, кисти и таз. Окклюзии, выход из кадра и low confidence уменьшают покрытие; причины низкого качества (освещение/смаз/камера) автоматически не диагностируются. Движение камеры, перспектива, поворот пациента и смена масштаба искажают результаты. Один ракурс не позволяет надёжно измерять 3D-движение.

Отчёт разделяет `measurement`, `algorithmic_observation` и `clinical_context` (уровень `literature_context`). Последний описывает проверенную литературу, не причинное объяснение наблюдений у пациента. Нет названий синдромов, вероятностей спастичности, назначений, дозировок или частоты процедур. Видео не оценивает боль, сердечно-сосудистое состояние, нестабильность/подвывих плеча, спастичность, чувствительность, когнитивные нарушения, головокружение, риск падения, заболевания и противопоказания. Раздел `safety_screen` показан перед реабилитационными направлениями. Индивидуальная реабилитация требует специалиста.

Для клинической валидации нужны согласованные ракурсы и задания, размеченные экспертом видео, эталонные измерения, проверка ошибки/согласия/воспроизводимости и чувствительности к пропускам на независимых пациентах. Выбор технических порогов сейчас не основан на клинической валидации.

## Evidence Service (пункты 11–14)

`ReviewedCatalogService` ищет по тематическим тегам только среди семи источников, содержательно проверенных 2 октября 2026: NICE NG236, UK/Ireland Stroke Guideline 2023 и пять Cochrane reviews. Учитываются только измерения со статусом `measured`, finite value, покрытием ≥60% и надёжностью high/medium. Выбор темы не означает, что обнаружена слабость, спастичность или патологическая компенсация. Порог асимметрии для назначения методов не используется.

Контракт `EvidenceRecord`: `id`, название, авторы/организация, год, URL/DOI, тип публикации, краткое резюме, дата проверки, `verified`, `verification_scope`, характер доказательств, раздел источника. Отсутствующий DOI остаётся `null`. Allowlist допускает только точные HTTPS-домены авторитетных источников; исключены коммерческие сайты, блоги, произвольные URL и подмена домена. Ранжирование: guidelines → systematic reviews/meta-analyses → RCT → observational → other, внутри уровня по году. Тип публикации не подменяет оценку GRADE.

Каждое утверждение и направление содержит источники **с проверенным содержанием** (`reviewed_content`), ссылки на конкретные измерения и `requires_clinician_review=true`. Правила в `recommendations/service.py` фиксированы, не генерируются LLM. Направления распределены по ЛФК, физиотерапии и эрготерапии. Отдельно отмечены условность электростимуляции, невозможность проверить критерии CIMT без кисти/пальцев, неопределённость сравнения bilateral/unilateral и различия NICE/UK по роботизированной тренировке (автоматически не предлагается). Обоснование метода не превращается в индивидуальное назначение: `applicability=not_assessed`; режим, частота, нагрузка, препараты не выдаются.

Каталог не является исчерпывающим или автоматически обновляемым систематическим обзором. Старые обзоры явно датированы и показаны после рекомендаций. После **180 дней от содержательной проверки** источник исключается из новых рекомендаций до повторной проверки; отображается причина. Повторная проверка требует прочитать источник и актуальные обновления, затем изменить `accessed_at`/версию каталога, не просто обновить дату. При повреждении каталога/непроверенной ссылке метрики сохраняются, клинический контекст не формируется.

Дополнительный поиск: `POST /api/studies/{id}/evidence` с `{"online": true, "topic": "upper_limb"}`. Интерфейс предлагает только темы, для которых имеются надёжные измерения. Запросы предопределены в `evidence/pubmed.py`; в NCBI передаются только общие термины, типы публикаций и окно последних пяти лет. Нет произвольного запроса и URL. Поиск выполняется через официальные ESearch/EFetch NCBI, до пяти записей; библиография сверяется по PMID, исключаются помеченные ретракции и записи без обязательных метаданных. Данные кэшируются до 24 часов с первоначальной датой доступа. Из результатов видны запрос, дата, авторы, год, URL/DOI и тип публикации. Поиск не является полным обзором; полнотекстовая критическая оценка новых публикаций пока выполняется специалистом.

`verification_scope=bibliographic_metadata` означает, что подтверждено существование записи, **а не её выводы или качество**. Такие результаты не входят в автоматические интерпретации/реабилитационные направления. Их краткое описание явно сообщает, что содержание не оценено; приложение не пересказывает непроверенный abstract как доказательство. DOI не придумывается. При сбое сети выводится предупреждение, сохраняются измерения и проверенный каталог. Поиск не использует внешнюю LLM и не отправляет медицинские данные.

Обновление без сети: `POST /api/studies/{id}/evidence` с `{"online": false}`. При запуске сервера ранее сохранённые завершённые отчёты без Evidence Service дополняются из локального каталога; повторная обработка видео не нужна. В интерфейсе также можно нажать «Обновить подбор» / «Добавить проверенные источники». JSON отчёта и `evidence.json` обновляются, landmarks/metrics не меняются. Удаление во время обновления получает 409, чтобы избежать гонки записи; затем удаляется и файл доказательств.

Тесты проверяют приоритет источников, доверенные домены, устаревание, обязательные citations, отсутствие рекомендаций при low confidence, разделение библиографии и доказательств, отсутствие пациентских данных в HTTP-запросах, деградацию при недоступности сети/каталога, сохранение и удаление. Проверен также реальный ESearch/EFetch запрос PubMed; unit-тесты используют MockTransport и не зависят от сети.

Проверка полного HTTP pipeline, включая онлайн-поиск: после подготовки публичного sample из раздела тестов выполните `python -m scripts.verify_local --online`. Это отправляет только общие термины в PubMed, проверяет сохранение контекста/доказательств и удаляет тестовое исследование. На 2 октября 2026: **37 тестов проходят**, production-сборка проходит, live PubMed API и HTTP pipeline проверены. Визуальная проверка во встроенном браузере среды разработки по-прежнему недоступна.

## Privacy

Обработка полностью на сервере, указанном при запуске: по умолчанию это ваш компьютер, `127.0.0.1`. Никакие видео/landmarks/отчёты не отправляются внешним AI API. Нет аналитики, внешних шрифтов, обучения на загрузках или patient names в названиях файлов. Скачивается только публичный файл модели из Google Storage. Данные сохраняются до явного удаления. API отдаёт `Cache-Control: no-store`, ограничивает origins для изменяющих запросов. DELETE удаляет оригинал, копию, landmarks, метрики и отчёт после окончания обработки. Оно не стирает уже скачанные копии, резервные копии ОС или блоки SSD гарантированно.

При нажатии «Найти в PubMed» NCBI получает фиксированный общий тематический запрос и стандартные сетевые сведения (например IP сервера). Значения метрик, сторона, тип пациентского задания, ID исследования и видео не передаются. Каталог не обращается к внешним сервисам. При удалении исследования также удаляется `evidence.json`; общий краткосрочный кэш публичной библиографии не содержит данных пациента.

**Это однопользовательский локальный MVP без аутентификации, шифрования хранилища и аудита.** Не открывайте порт в общую сеть и не размещайте на публичном хостинге с реальными медицинскими видео. Для клиники потребуются аутентификация/роли, TLS, шифрование и управление ключами, retention policy, аудит, согласия, изоляция workers и проверка применимых требований к медицинским данным. При использовании медицинских видео заранее согласуйте доступ и включите шифрование диска/ограничения ACL на папку `data`.

## Анкета пациента и персонализированный разбор

На странице загрузки доступна анкета верхней части тела: общие сведения, диагноз и течение болезни, операции, сопутствующие заболевания, препараты, боль, ограничения врача, очная оценка силы/тонуса/чувствительности/кисти, бытовые трудности, цели и история реабилитации. Используйте код пациента вместо ФИО. Пустые поля и «неизвестно» не означают отсутствие проблемы. Данные пациента не передаются в PubMed или внешние AI API.

Анкета сохраняется как `data/<study_id>/patient.json` вместе с видео, входит в JSON отчёта (`patient_profile`) и полностью удаляется с исследованием. Список исследований не содержит полей анамнеза. Историю можно изменить в разделе «Пациент и персонализированный разбор» после завершения анализа; отчёт обновляется без повторного inference. Экспорт отчёта содержит медицинскую историю — учитывайте это при передаче файла.

Дополнительные API:

- `GET /api/patient-form` — поля, диапазоны, варианты и значения по умолчанию.
- `GET /api/studies/{id}/patient` — сохранённая анкета; для старого исследования пустая анкета.
- `POST /api/studies/{id}/patient` — валидированная анкета JSON; ответ содержит `patient_profile` и обновлённый `report`.
- `GET /api/studies/{id}/files/patient` — экспорт анкеты.

Раздел `personalized` содержит цели, пригодные измерения выбранной стороны и корпуса, недостающие сведения, приоритеты медицинской оценки и методы для обсуждения с обязательными источниками и проверками. Правила имеют `rule_version=1.0`. Свободный текст истории и препаратов сохраняется как сообщённая информация; он не интерпретируется автоматически как диагноз, противопоказание или допуск к нагрузке. Данные не подтверждаются независимо приложением.

Существующий каталог применяется только к взрослым (18+) с указанным и подтверждённым врачом инсультом. При другом/неизвестном диагнозе, неизвестном возрасте или у ребёнка персонализированные методы из этого каталога не формируются. При сообщённых новых неврологических симптомах или симптомах при нагрузке подбор приостанавливается до медицинской оценки. Боль, нестабильность, недавняя травма и указанные ограничения требуют проверки перед выбором методов. CIMT сопоставляется с сообщёнными очными углами только при указанных специалисте и дате; даже достижение критериев не подтверждает пригодность.

Содержательная основа ограничений — [NICE NG236: assessment, movement, shoulder pain и spasticity](https://www.nice.org.uk/guidance/ng236/chapter/Recommendations), проверена при разработке раздела 2 октября 2026. Персонализированный разбор не назначает индивидуальное лечение, препараты, дозы или нагрузку. Это контекст для очной оценки специалистом, ограниченный технической точностью видео и полнотой анкеты.
